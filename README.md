# Clip Maker

YouTube の切り抜きを「どこを・どの字幕で」だけ決めて作るツール。

## Chrome 拡張（`extension/`）— 拡張だけで切り抜き動画ができる
1. `chrome://extensions` → デベロッパーモード → 「パッケージ化されていない拡張機能を読み込む」→ `extension/`
2. YouTube の動画ページで拡張アイコン → **開始・終了・長さ**（最大 60 秒。どれを変えても残り 2 つが自動で追随。開始と終了には「▶ 今の位置」ボタン＝停止中の再生位置がそのまま入る）→ **「吸い出して編集画面を開く」**
3. 編集画面で
   - ① 範囲を直す（開始・終了・長さ＋「▶ 今の位置を開始に／終了に」→「🔄 この範囲で吸い出し直す」）
   - ② 出力を **横（16:9・1920×1080）／縦（Shorts・9:16・1080×1920）** から選ぶ。縦は元画面の黄色い枠をドラッグして切り出す位置を決める
   - ② 隠したい所は **左の「元画面」をドラッグ** して黒い四角で覆う（複数可・表示区間も指定可）
   - ② 右の「出来上がり」を ▶ で再生すると、時間どおりに字幕・チャット・四角が出る（チャットは位置・件数・表示秒数・大きさを指定。乗せない設定も可）
   - ③ 字幕を修正（行の編集・削除・追加。▶ で YouTube タブがその位置を再生＝音声確認）
   - **④「動画を作る」** → `ダウンロード/clip-maker/clip_<id>_<秒>_yoko.mp4`（縦は `_tate`）
4. 「動画を作る」の仕組み: YouTube タブが前に出て、切り抜き区間を実時間で再生しながら録画する（60 秒の切り抜きは約 60 秒）。
   映像に四角・字幕・チャットを描き込み、音声つきの mp4（H.264 + AAC）で保存する。**録画中は YouTube タブを表示したまま待つ**（タブを隠すと映像が止まるためエラーにする）。
   - 画質は再生中の画質まで（YouTube の画質設定を上げてから作ると綺麗になる）。録画中は音が鳴る（ミュートのままだと無音の動画になるため一時的に解除し、終わったら戻す）。
   - mp4 で録画できないブラウザでは webm になる（拡張子も webm。その旨を表示する）。

### 字幕・チャットについて
- 字幕は YouTube 側に字幕トラック（自動生成含む）がある動画だけ取れる。無い動画は「字幕を追加」で手入力する。
- チャットは配信アーカイブのチャットリプレイ（動画下のコメント欄ではない）。リプレイの無い動画では取れない。

## PC プロ版（`pro/`・任意。拡張だけで動画は作れるので必須ではない）
```
pip install ./pro          # 要 ffmpeg（PATH）
clipmaker watch            # 常駐: ダウンロード/clip-maker を監視し、拡張で保存すると自動で mp4 に焼き付ける
clipmaker render ダウンロード/clip-maker/<id>_<秒>.clip.json   # 1 本ずつ手動でも可（同名 .srt / .chat.json があれば字幕・チャットを焼き込む）
```
→ 保存した 3 ファイルと同じフォルダに `<id>_<秒>.mp4`（watch）／`out/` 配下（render）。上限 10 分。
- 字幕とチャットは 1 つの `.burn.ass` にまとめて焼く（字幕＝下中央・白文字黒縁、チャット＝指定枠に新しい順で積む。スパチャ金額は黄）。位置・大きさは拡張のプレビューと同じ比率。
- 縦（`frame.mode=portrait`）は 1920×1080 に揃えてマスク → `crop` → 1080×1920 に拡大 → 字幕・チャット、の順。
- `chat_overlay.enabled` なのに chat.json が無いときは黙って字幕だけにせずエラーファイルに書く。
- watch の常駐登録は `pro/watch_downloads.bat` をスタートアップに置く（このリポジトリでは登録済み）。
- 焼き付け失敗は同フォルダの `<base>.render_error.txt` に原因と再実行方法を書く（黙って握りつぶさない）。json を保存し直すと自動で再挑戦。
- 字幕 0 件の srt は「焼くものが無い」として字幕なしで焼く（libass は空 srt を開けず落ちるため明示スキップ）。
- 元動画キャッシュは `ダウンロード/clip-maker/.cache/` に残す（同じ区間の 2 回目以降は数秒で焼ける）。

## 既知のリスク
- YouTube 規約: 切り抜きの公開は元動画の権利者の許諾が要る（ツールはユーザーの責任で使う）。
- 字幕は動画側にトラックがある場合だけ取れる（無い場合はエラー表示。黙って空にしない）。
- Chrome Web Store 審査: `downloads` 権限の用途説明が必要。

## テスト・実機確認（2026-08-26）
```
python -m pytest tests -q          # プロ版の単体 27 件（ffmpeg/yt-dlp は差し替え）
cd e2e && npm i && node extension_e2e.js [videoId] [start秒] [length秒]   # 拡張の実機 E2E（本物の Chrome + YouTube、窓が一瞬開く）
```
確認済みの範囲（標準サンプル動画 `qpArCzp00yM`・開始 1:24:09=5049s）:
- 2026-09-28（v0.7.0）: 拡張だけで動画を作る方式に変更。`e2e/extension_e2e.js` を実機（本物の Chrome + YouTube）で実行し `E2E_OK`。
  吸い出し → 元画面ドラッグで四角 → プレビュー再生 → 「動画を作る」で横 1920×1080 と縦 1080×1920 の mp4（H.264 + AAC・音声あり）が `ダウンロード/clip-maker/` に出るのを確認。字幕・チャット・四角の描き込みは静止画で確認。
- 拡張: Chrome 151 で 2 段階フロー本線（popup「吸い出して編集画面を開く」→ 編集タブでマスクをドラッグ描画 → 保存）で `clip.json`（マスク矩形入り）/ `srt`（字幕 8 行・実データ）/ `chat.json` の 3 ファイルが `ダウンロード/clip-maker/` に落ちる（`E2E_OK`）。
- チャットの取り方: チャット iframe（`/live_chat_replay`）は同一オリジンなので contentDocument を直接読む。リプレイは再生位置に同期するため、切り抜き終端へシークして件数が安定するまで待ってから収集（チャットリプレイの無い動画は明示エラー）。
- プロ版: 上で落ちた `clip.json` + `srt` をそのまま `clipmaker render` に通し、16 秒の h264/aac mp4 に字幕とドラッグ位置どおりの黒矩形が焼き込まれたのを画像で確認。字幕 ON/OFF・マスク・5〜30 秒の 6 本長さ違い＝計 9 本を ffprobe で長さ検証済み。
- 区間ダウンロード: 長時間配信でも全編は取らない（必要区間の前後 5 秒だけ）。https 直結だと YouTube に速度を絞られ 26 秒区間が 70 分超になるため HLS(m3u8) を優先（同区間が約 1 分・約 9MB）。
- 字幕の取り方: 拡張から timedtext を直接 fetch すると YouTube が空を返す（pot トークン必須）ため、プレーヤー自身の字幕通信を `inject.js` で横取りする。headless / 自動操作フラグ付きの Chrome でも空になるので E2E は通常ウィンドウで回す。
- 編集画面のプレビュー: YouTube 埋め込み iframe は拡張ページ（referer 無し）だとエラー 153 で拒否される（2026-08-26 実機で確認）ため、吸い出し時に `<video>` を canvas に描いて実コマ 3 枚を撮り編集画面へ渡す（YouTube は MSE 供給なので canvas は汚染されない）。
